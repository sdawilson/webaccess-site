Worksheets on live data

The Spreadsheet control puts a workbook on a form. Lay it out as you would in Excel, with titles, formulas and formatting, then choose the row where the records of a table or query go.

  • Records are inserted at the row you choose. What's above and below them stays, and a total beneath stretches as records come and go
  • A formula beside the first record fills down, one for every record
  • Change a cell and its record is saved at once. Or turn Auto Update off, and your code decides when, with Data.Update
  • Allow Edits, Allow Inserts and Allow Deletes, set for each workbook
  • Lock the layout, so Users can change the records and nothing else
  • Link a workbook to the form's current record, the way a subform is linked
  • Import and export Excel files, with their formulas, formats and column widths
  • Excel's objects in VBA: Workbook, Worksheet, Range and ListObject, with SheetChange and SheetSelectionChange events
  • PivotTable and PivotChart views work from the same table or query

Tables and queries

Design tables on screen, with a type, a format and rules for every field, then query them by dragging fields into a grid. If you know Microsoft Access, they're the field types and the grid you're used to, and SQL view speaks Access SQL.

  • Number sizes from Byte to Double, Currency to four places, and regional settings for dates, numbers and money
  • Calculated fields such as [Unit Price]*[Quantity], and a Format for every field
  • Validation rules and input masks, for each field and the whole table, kept by the database itself
  • Relationships between tables, with referential integrity, cascade update and cascade delete, kept by the database itself
  • Join by dragging between field lists; click a join line to make it an outer join. Related tables join themselves
  • Parameters in [brackets] are asked for when the query runs, or declared with a data type in Query Parameters
  • Change, add and delete records through a query, in its datasheet or a form on it, when each row is one record of the tables behind it
  • Crosstab queries in the grid, union queries in SQL view, and DLookup and the other domain functions inside a query
  • SQL you've written, or imported, turns back into the design grid whenever the grid can say the same thing
  • Find and Replace, and Filter by Form, on any datasheet
  • Import tables, queries and relationships from .accdb and .mdb, and data from Excel and CSV; export to Excel and CSV

Forms

The form designer works the way Access's does: a field list to drag from, a gallery of controls, Form Header, Detail and Form Footer sections, and a property sheet for every control.

  • Single, Continuous and Datasheet views, with subforms nested three deep
  • Text boxes, multi-column combo and list boxes, option groups, tab controls, buttons, images and hyperlinks
  • Tree View, List View, Image List, Progress Bar, Slider and UpDown, built in and in the Controls gallery like any other control. They work the way the Windows Common Controls do in Access, so code written for those runs
  • A Web Browser Control, showing a page from an address, a field or an expression
  • A Chart control modelled on Access's modern one: column, bar, line, area, combo, pie, doughnut, scatter and bubble, from a table, a query or code, and able to follow the main form's record as a subform does
  • 27 chart palettes, eleven of them checked for colour blindness, or make your own. Format a chart's series and points from code
  • A look for each database: Classic or Modern controls, rounded corners, a focus highlight, a system colour and an accent, and a default font that its worksheets follow too
  • Datasheet view is the form itself as a grid, so its code, combo boxes, validation and conditional formatting all work, with its own font, colours, gridlines and frozen columns
  • Find and Replace, Filter by Form, and Print for the current record or all of them
  • Calculated controls such as =[Quantity]*[Unit Price] and =Sum([Line Total])
  • The properties and events you know from Access: tab order, input masks, validation, NotInList, and mouse and key events
  • Pop-up and modal forms, anchoring, and forms that hide the commands to run your application

Reports

Lay out a report in the sections Access uses, group and total it in the Group, Sort, and Total pane, then check the pages in Print Preview before printing.

  • Report Header and Footer, Page Header and Footer, and a header and footer for each group
  • Group by value, first letters, ranges, or dates by week, month, quarter or year
  • Sum, Average, Count, Max and Min in every group footer, plus Running Sum and Hide Duplicates
  • Subreports linked by master and child fields, and Can Grow and Can Shrink on text boxes and sections
  • A module behind each report: Open, No Data, Page, and each section's Format and Print events
  • A4, A3, A5, Letter or Legal, portrait or landscape; print, or save as PDF
  • DoCmd.OpenReport from code, filtered to the records you choose, and reports imported from Access

PivotTable and PivotChart, back again

Access 2013 removed them. In Web Access Builder they're form views again: drag fields to rows, columns and totals, group dates by year, quarter or month, then switch to a chart of the same layout.

  • Sum, Count, Average, Min, Max, StDev and Var, with subtotals and grand totals
  • Show As a percentage of the row, column or grand total
  • Column, bar, line, area, pie, doughnut and scatter charts, stacked or 100%
  • Totals are worked out by the database, so large tables stay quick
  • PivotCharts in code through Access's ChartSpace object model

No code, macros, or VBA

Forms, queries and worksheets need no code at all. Add a macro when a button should do something. Write VBA when you need more, in an editor with IntelliSense as you type, and breakpoints, stepping, Locals, Watches and the Immediate window.

  • Excel's Workbook, Worksheet and Range on a Spreadsheet control, and worksheet change events
  • Form and control events, Me, DoCmd, MsgBox and InputBox
  • DLookup, DCount and DAO recordsets: Edit, AddNew, Update, FindFirst
  • More of DoCmd: FindRecord, SearchForRecord, SetFilter, and OutputTo and TransferSpreadsheet to export as a download; and the Screen and Application objects
  • Compile errors as VBA shows them: “Compile error: Expected: Then or GoTo”
  • Transactions from code: BeginTrans, CommitTrans and Rollback
  • Macros too: Macro Design with If blocks and submacros, AutoExec, macros behind events, and DoCmd.RunMacro
  • Explain Error and Fix Error: AI says what went wrong and offers a fix you can apply. The assistant writes modules and macros too
  • References for statistics, UK bank holidays and British National Grid coordinates

An assistant that builds it with you

Say what you need in plain words: a table, a query, a form, a report, or a small application. The assistant looks at what's in your database, shows you a plan, and builds it only when you say go ahead.

  • It makes tables, relationships, queries, forms, reports, macros and code with the same designers you'd use, so you can open and change everything afterwards
  • Nothing changes until you approve its plan. Don't like the plan? Say what to change
  • Its last build can be undone: what it made is removed, and what it changed is put back as it was
  • It's sent the design of your database, not the records. If it wants to see a few rows of a table it asks, each time, and you can say no
  • For Admins only. Users and Guests never see it
  • It can be switched off for an account, and then its buttons aren't there at all
  • In the code window, Explain Error and Fix Error say what went wrong and offer a fix

The assistant is new, and it's an AI: it can be wrong, so look over what it makes. It isn't in the public demo; a free account has a small monthly allowance for it.

Simple to build. Free to distribute.

Someone who knows the work builds it. Everyone else uses it from a link, in a runtime with no design tools, without paying for anything or installing anything.

  1. Build it

    Admins design the tables, worksheets, forms, reports and code. An Admin seat is the only thing you pay for.

  2. Share it

    Invite people to a database by email: as a User, who works with the data, or a Guest, who can only read it. They open it from a link.

  3. They use the runtime

    No design tools, no Navigation Pane, no Design view and no code window: just your forms, worksheets and reports, starting at the form you choose.

Free for up to 10 people

Up to 10 people use each database free, Users and Guests together, while it runs on SQLite. There's no per-user licence. Their access stays free for as long as your subscription is active.

  • Locked down properly. Nothing in a database's code can bring the design tools back, and the server checks every request, so hiding the tools isn't the only protection.
  • Errors come back to you. If something goes wrong, the person sees a plain message and carries on, and the error is logged for the database's Admins to see when they next open it.
  • See what they see. Preview as User opens your database in the runtime, exactly as they'll get it.
  • More than 10 people? A database can move to a hosted SQL database for more, at a fee that covers its hosting.
