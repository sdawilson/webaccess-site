VBA, moved on

The VBA you have runs as it is. New code can use the additions that twinBASIC and VB.NET made familiar, so it's shorter and easier to read.

  • Class constructors: Sub New in a class, then Set c = New Customer("Abbey Mill", 250)
  • AndAlso, OrElse, IsNot and If(test, a, b)
  • Continue For, Continue Do, Exit While and Return value
  • Dim n As Long = 5 and For i As Long = 1 To 10
  • n += 1 and the other compound operators, with << and >>
  • Try … Catch … Finally, beside On Error
  • Values written into a string: $"Total: {n:Currency}"
  • Inline functions: SortArray names, Function(a, b) Len(a) - Len(b), and delegates with AddressOf
  • For Each over a class of your own, and default members, as in Access

Code that uses the additions won't run in Access. The Immediate window notes the first use of each, and Options turns the notes off.

Or write the event in Python or JavaScript

VBA isn't the only choice. Press … beside an event and Choose Builder offers Code Builder in VBA, Python or JavaScript, with your default picked. Each event runs one procedure, and one form can mix all three.

  • def cmdSave_Click(form): or export function cmdSave_Click(form), written for you
  • Arguments come as event: event.Cancel = True cancels a Before Update, event.KeyCode = 0 swallows a key
  • Python and JavaScript call the app as they run: message boxes, DoCmd, recordsets, DLookup, and the form's VBA procedures
  • VBA calls them back: Forms!Orders.WithVat(19.99) runs a function in the form's Python module
  • TempVars pass values between VBA, Python, JavaScript, macros and queries
  • Python libraries in References: pandas, NumPy, Matplotlib, SciPy, scikit-learn and Pillow; JavaScript ones for statistics, dates, fuzzy matching and more

What's different in a browser

It's VBA, but it isn't Windows. These are the things to know before you bring code across.

No Windows API
Declare statements and CreateObject for desktop applications have nothing to call in a browser. Dictionary and RegExp are built in.
Files are the browser's
Code can't read or write the disk directly. Imports and exports go through the browser's file picker and downloads.
Not Excel's whole object model
Workbook, Worksheet, Range and ListObject are there for the Spreadsheet control. Charts, shapes and other Office applications are not.
Python and JavaScript where you'd use a DLL
Where desktop code would call a DLL, write a Python or JavaScript module and call its functions from VBA. They run in a sandbox, with no access to the network or your files.

The Programmer's Guide lists what's supported, statement by statement, and Differences from Access lists what isn't.
