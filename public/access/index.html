Bring your database across

Moving an existing Access application is mostly familiar work, done once.

  1. Import tables and queries

    Open your .accdb or .mdb in Import Objects. Tables keep their fields, data types, calculated fields and AutoNumber values; queries are rebuilt from the database's own design; relationships come with the tables.

  2. Bring in forms, reports, macros and code

    Run our export module once in Access. It writes your forms, reports, macros and modules out to a folder and changes nothing. Import the folder, and each form and report comes with its layout, its code and its macros, with a list of anything that couldn't come across.

  3. Check the code

    Compile shows what needs changing, such as file access or a Declare that a web page can't do. The References your code uses are ticked for you.

  4. Share it

    Invite people by email from File > Share, as a User or a Guest. They open your database from the link, in the runtime, and up to 10 per database are free.

Questions

Is this Microsoft Access?

No. Web Access Builder is an independent product that works the way Access does. It runs in a browser, doesn't need Access installed, and isn't made by or connected with Microsoft.

Can I open my .accdb file in it?

Mostly. Import Objects brings in tables, with their calculated fields and AutoNumber values, and queries, straight from the file. Forms, reports, macros and modules come through a small export module you run once in Access; it saves them with Access's own SaveAsText and changes nothing.

Will my VBA run?

Much of it, as written: form and control events in Access's order, Me, DoCmd, MsgBox, DLookup and DCount, DAO recordsets, error handling and class modules. Things a web page can't do, such as Shell, file access, Windows DLLs and automating Excel, are marked in the code window, and only that line fails if it runs. JavaScript modules stand in for DLLs.

Does it do reports?

Yes: grouping, totals, page numbers and Print Preview with page size, margins and orientation. Subreports, Can Grow and Can Shrink, and a module behind each report with its events. Print them, or save them as PDF from the print dialog, and open them from code with DoCmd.OpenReport. Reports come across from Access with the export module.
