Python and JavaScript, as first-class as VBA

Write a button's Click, a text box's Before Update or a report's Format in Python or JavaScript, just as you would in VBA. The code calls the app as it runs, and pandas, NumPy and Matplotlib are a tick away. It all runs in your browser, with nothing to install.

Choose the language for each event

In Design view, press … beside an event. Choose Builder offers the Macro Builder, the Expression Builder, and Code Builder in VBA, Python or JavaScript, with your default picked (set it in Options). The procedure's first lines are written for you.

  • One form can mix them: its Load in VBA, a text box's After Update in Python, a button's Click in JavaScript. Each event runs one procedure
  • The names are VBA's: def cmdSave_Click(form):, export function Form_Load(form)
  • The form comes first, standing in for Me; an event's arguments come as event: event.Cancel = True, event.KeyCode = 0, event.Response
  • A form's Python and JavaScript modules sit beside its VBA one, and are renamed, copied, exported and imported with it
  • Compile catches an event written in two languages, and a procedure for a control the form hasn't got
  • Reports too: Detail_Format(report, event) can leave a record out

It calls the app as it runs

Python and JavaScript reach the same objects VBA does, with VBA's behaviour, error numbers and the signed-in person's rights. In Python it's plain code on the real form; in JavaScript each call to the app is awaited.

  • MsgBox and InputBox, DoCmd.OpenForm and the rest of DoCmd, other forms and reports
  • Recordsets, DLookup, DSum and the other domain functions, on your tables and queries
  • Your VBA: the form's own procedures, a standard module's, and VBA's built-in functions. VBA calls back: Forms!Orders.WithVat(19.99)
  • TempVars, shared by VBA, Python, JavaScript, macros and queries
  • Errors from the app as AccessError, with VBA's numbers; uncaught, Debug opens the module at the line
  • Every constant VBA knows, vbYesNo to acNormal, with nothing to import

A minute and a half, with narration and captions: modern VBA, the libraries in References, a Python module called from VBA, a form passed to Python, a Matplotlib chart on a form, and JavaScript.

Python modules VBA can call

Not every piece of Python belongs to an event. Insert > Python Module puts one beside the VBA modules, and VBA calls its functions by name: Debug.Print Summary.describe(Array(14, 18, 21)).

  • Real Python (3.14), not a lookalike, with its standard library
  • Tick the libraries a database uses in References: pandas, NumPy, Matplotlib, SciPy, scikit-learn and Pillow
  • A VBA array arrives as a list, and a recordset as its rows
  • Return a tuple and VBA gets an array; return a dict and it gets JSON
  • A Python error stops the VBA as a run-time error, with Python's message and line
  • Python colouring, indenting and a compile check in the code window

Charts and pictures on a form

A Matplotlib figure or a Pillow image comes back to VBA as a picture, and an Image control's PictureData shows it.

  • Any chart Matplotlib draws, on the data your queries return
  • Pictures made or changed with Pillow
  • Shown when the form opens, or when a button is clicked

JavaScript too

Everything above works in JavaScript: event procedures, modules VBA calls, and the app's objects. A call to the app is awaited, in an async function: await DoCmd.OpenForm(…), await MsgBox(…).

  • Libraries in References: statistics, from means to linear regression; dates, with working days, UK bank holidays and financial years; fuzzy matching; coordinates, CSV, hashes and UUIDs
  • The form is a copy read without waiting; what the code sets goes to the app before each awaited call, and the copy comes back up to date
  • Works in every browser

Good to know

Python and JavaScript here run in the browser, so they work a little differently from code on a server.

No network or files
They run in a sandbox. They reach the app's forms, data and commands, and can't reach the internet or your disk.
Which browsers
Python calls the app as it runs in current Chrome, Edge and Firefox, and Safari 27 or later. In older Safari, and on iPhones and iPads before iOS 27, Python event code works on a copy of the form and can't call the app. JavaScript works everywhere. Phones haven't been tested with the large libraries.
A few seconds to start
Python starts as a database opens when one of its forms uses it, then stays ready.
Events that run often
On Render, Mouse Move, Key Press, Timer and a report's Format take a few milliseconds a run in Python or JavaScript, and a fraction of one in VBA. For long reports and lists, VBA is quicker; Choose Builder says so.
Finding faults
print() and console.log write to the Immediate window, and an error opens the module at its line. Breakpoints and IntelliSense are for VBA; they aren't in Python or JavaScript modules yet.

The Programmer's Guide covers event procedures in Python and JavaScript in detail, and Code by example has working examples to copy.
