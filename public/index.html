New: sharing and the runtime

Simple to build. Free to distribute.

That was always the deal with Microsoft Access. Someone who knows the work builds the database, and everyone else uses it through the free Access Runtime, without buying Access. Web Access Builder keeps that deal, on the web.

  1. Build it

    Admins design the tables, queries, forms, reports and VBA. An Admin seat is the only thing you pay for.

  2. Share it

    Invite people to a database by email: as a User, who works with the data, or a Guest, who can only read it. They open it from a link.

  3. They use the runtime

    No design tools, no Navigation Pane, no Design view and no code window: just your forms and reports, starting at the database's Display Form.

Free for up to 10 people

Up to 10 people use each database free, Users and Guests together, while it runs on SQLite. There's no per-user licence, just as there wasn't with the Access Runtime. Their access stays free for as long as your subscription is active.

  • Locked down properly. Nothing in a database's code can bring the design tools back, and the server checks every request, so hiding the tools isn't the only protection.
  • Errors come back to you. If something goes wrong, the person sees a plain message and carries on, and the error is logged for the database's Admins to see when they next open it.
  • See what they see. Preview as User opens your database in the runtime, as Access's /runtime switch does.
  • More than 10 people? A database can move to a hosted SQL database for more, at a fee that covers its hosting.

Tables and queries

Design tables with the field types Access uses, then query them in the grid you've always used. Criteria are written the Access way, and SQL view speaks Access SQL.

  • Number sizes from Byte to Double, Currency to four places, and regional settings for dates, numbers and money
  • Calculated fields such as [LengthM]*[WidthM], and a Format for every field
  • Validation rules and input masks, for each field and the whole table, kept by the database itself
  • Join by dragging between field lists; click a join line to make it an outer join
  • Parameters in [brackets] are asked for when the query runs, or declared with a data type in Query Parameters
  • Change, add and delete records through a query, in its datasheet or a form on it, when each row is one record of the tables behind it
  • Crosstab queries in the grid, and union queries in SQL view
  • SQL you've written, or imported, turns back into the design grid whenever the grid can say the same thing
  • Import tables and queries from .accdb and .mdb, and data from Excel and CSV; export to Excel and CSV

Forms

The form designer works the way Access's does: a field list to drag from, a gallery of controls, Form Header, Detail and Form Footer sections, and a property sheet for every control.

  • Single, Continuous and Datasheet views, with subforms nested three deep
  • Text boxes, multi-column combo and list boxes, option groups, tab controls, buttons, images and hyperlinks
  • Tree View, List View, Image List and Progress Bar, built in and in the Controls gallery like any other control. They work the way the Windows Common Controls do in Access, so code written for those runs
  • A Chart control modelled on Access's modern one: column, bar, line, area, combo, pie, doughnut, scatter and bubble, from a table, a query or code, and able to follow the main form's record as a subform does
  • Datasheet formatting kept with the form: font, colours, gridlines, frozen columns and row height, for its Datasheet view and datasheet subforms
  • Calculated controls such as =[LengthM]*[WidthM] and =Sum([Estimate])
  • The properties and events you know from Access: tab order, input masks, validation, NotInList, and mouse and key events
  • Pop-up and modal forms, anchoring, and forms that hide the commands to run your application

Reports

Lay out a report in the sections Access uses, group and total it in the Group, Sort, and Total pane, then check the pages in Print Preview before printing.

  • Report Header and Footer, Page Header and Footer, and a header and footer for each group
  • Group by value, first letters, ranges, or dates by week, month, quarter or year
  • Sum, Average, Count, Max and Min in every group footer, plus Running Sum and Hide Duplicates
  • Subreports linked by master and child fields, and Can Grow and Can Shrink on text boxes and sections
  • A module behind each report: Open, No Data, Page, and each section's Format and Print events
  • A4, A3, A5, Letter or Legal, portrait or landscape; print, or save as PDF
  • DoCmd.OpenReport from code, filtered to the records you choose, and reports imported from Access

PivotTable and PivotChart, back again

Access 2013 removed them. In Web Access Builder they're form views again: drag fields to rows, columns and totals, group dates by year, quarter or month, then switch to a chart of the same layout.

  • Sum, Count, Average, Min, Max, StDev and Var, with subtotals and grand totals
  • Show As a percentage of the row, column or grand total
  • Column, bar, line, area, pie, doughnut and scatter charts, stacked or 100%
  • Totals are worked out by the database, so large tables stay quick
  • PivotCharts in code through Access's ChartSpace object model

VBA, with the debugger you're used to

Open the code window and it's the VBA editor: a module behind each form, standard and class modules, IntelliSense as you type, and breakpoints, stepping, Locals, Watches and the Immediate window.

  • Form and control events, Me, DoCmd, MsgBox and InputBox
  • DLookup, DCount and DAO recordsets: Edit, AddNew, Update, FindFirst
  • More of DoCmd: FindRecord, SearchForRecord, SetFilter, and OutputTo and TransferSpreadsheet to export as a download; and the Screen and Application objects
  • Compile errors as VBA shows them: “Compile error: Expected: Then or GoTo”
  • Explain Error and Fix Error: AI says what went wrong and offers a fix you can apply
  • References for statistics, UK bank holidays and British National Grid coordinates

Bring your database across

Moving an existing Access application is mostly familiar work, done once.

  1. Import tables and queries

    Open your .accdb or .mdb in Import Objects. Tables keep their fields, data types, calculated fields and AutoNumber values; queries are rebuilt from the database's own design.

  2. Bring in forms, reports and code

    Run our export module once in Access. It writes your forms, reports and modules out to a folder and changes nothing. Import the folder, and each form and report comes with its layout and its code, with a list of anything that couldn't come across.

  3. Check the code

    Compile shows what needs changing, such as file access or a Declare that a web page can't do. The References your code uses are ticked for you.

  4. Share it

    Invite people by email from File > Share, as a User or a Guest. They open your database from the link, in the runtime, and up to 10 per database are free.

Questions

Can we use it for real work yet?

Not yet. Web Access Builder is in active development, so features are still changing and there may be bugs. Please test it with copies of your data, keep your Access database as the working version, and tell us what you find. We'll say here when it's ready for production use.

Is there a demo?

Yes: demo.webaccessbuilder.com. Click Try the demo for your own copy of the Fieldfare Traders sample database, with full design rights. There's no sign-up, and your copy isn't kept: it's deleted when you end the demo, after 30 minutes without use, after 2 hours, or when the server restarts. Anything you send with the Feedback button is kept, so we can read it.

What will it cost?

Nothing while we're testing. After that, we plan to charge £15 a month or £99 a year for each Admin, the people who design. Up to 10 people use each database free in the runtime. For more than 10 on one database, talk to us.

Do the people who use my database need a licence?

No. As with the Access Runtime, the people you share a database with don't pay: up to 10 per database, Users and Guests together, while it runs on SQLite. Their access stays free for as long as your subscription is active. They use its forms and reports, and can't open Design view or the code.

Is this Microsoft Access?

No. Web Access Builder is an independent product that works the way Access does. It runs in a browser, doesn't need Access installed, and isn't made by or connected with Microsoft.

Can I open my .accdb file in it?

Mostly. Import Objects brings in tables, with their calculated fields and AutoNumber values, and queries, straight from the file. Forms, reports and modules come through a small export module you run once in Access; it saves them with Access's own SaveAsText and changes nothing. Macros are next.

Will my VBA run?

Much of it, as written: form and control events in Access's order, Me, DoCmd, MsgBox, DLookup and DCount, DAO recordsets, error handling and class modules. Things a web page can't do, such as Shell, file access, Windows DLLs and automating Excel, are marked in the code window, and only that line fails if it runs. JavaScript modules stand in for DLLs.

Does it do reports?

Yes: grouping, totals, page numbers and Print Preview with page size, margins and orientation. Subreports, Can Grow and Can Shrink, and a module behind each report with its events. Print them, or save them as PDF from the print dialog, and open them from code with DoCmd.OpenReport. Reports come across from Access with the export module.

Where is our data kept?

Each database is its own SQLite file on our servers in London, backed up every night, with copies kept for 30 days. Admins can download a complete copy at any time with Back Up Database.

Who can change the design?

Only Admins. They design tables, queries, forms, reports and code, and decide who can open each database. Everyone else uses what's been built, without the design tools: as a User, who works with the data, or a Guest, who can only read it.
