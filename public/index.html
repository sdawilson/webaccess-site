If you've built in Access, you already know it

Web Access Builder isn't a new way of working that looks a bit like Access. It's the Access way of working, kept on purpose, down to the names of things.

Tables and queries

Design tables with Access's field types, then query them in the grid you've always used. Criteria are written the Access way, and SQL view speaks Access SQL.

  • Number sizes from Byte to Double, Currency to four places, UK dates throughout
  • Join by dragging between field lists; click a join line to make it an outer join
  • Parameters in [brackets] are asked for when the query runs
  • Import from .accdb, .mdb, Excel and CSV; export to Excel and CSV

Forms

The form designer works the way Access's does: a field list to drag from, a gallery of controls, Form Header, Detail and Form Footer sections, and a property sheet for every control.

  • Single, Continuous and Datasheet views, with subforms nested three deep
  • Text and combo boxes, list boxes, option groups, tab controls, buttons, images and hyperlinks
  • Calculated controls such as =[LengthM]*[WidthM] and =Sum([Estimate])
  • Pop-up and modal forms, anchoring, and forms that hide the ribbon to run your application

Reports

Lay out a report in Access's sections, group and total it in the Group, Sort, and Total pane, then check the pages in Print Preview before printing.

  • Report Header and Footer, Page Header and Footer, and a header and footer for each group
  • Group by value, first letters, ranges, or dates by week, month, quarter or year
  • Sum, Average, Count, Max and Min in every group footer, plus Running Sum and Hide Duplicates
  • A4, A3, A5, Letter or Legal, portrait or landscape; print, or save as PDF

PivotTable and PivotChart, back again

Access 2013 removed them. In Web Access Builder they're form views again: drag fields to rows, columns and totals, group dates by year, quarter or month, then switch to a chart of the same layout.

  • Sum, Count, Average, Min, Max, StDev and Var, with subtotals and grand totals
  • Show As a percentage of the row, column or grand total
  • Column, bar, line, area, pie, doughnut and scatter charts, stacked or 100%
  • Totals are worked out by the database, so large tables stay quick

VBA, with the debugger you're used to

Open the code window and it's the VBA editor: a module behind each form, standard and class modules, IntelliSense as you type, and breakpoints, stepping, Locals, Watches and the Immediate window.

  • Form and control events, Me, DoCmd, MsgBox and InputBox
  • DLookup, DCount and DAO recordsets: Edit, AddNew, Update, FindFirst
  • Compile errors as VBA shows them: “Compile error: Expected: Then or GoTo”
  • Explain Error and Fix Error: AI says what went wrong and offers a fix you can apply
  • References for statistics, UK bank holidays and British National Grid coordinates

What changes when it's on the web

You design the same way. What's different is everything after that: getting it to people, keeping them up to date, and keeping the data safe.

With desktop AccessWith Web Access Builder
Install Access or the Runtime on every PCOpen a link in any modern browser, on Windows, Mac or a tablet
Split the database, and keep the back end on a shared driveOne database on the server. There's nothing to split or copy round
Send everyone a new front end after each changeSave a change and everyone has it next time they open the form
VPN or remote desktop to work from homeSign in from anywhere over HTTPS
Anyone with the file can open Design viewAdmins design. Users open what you've built and work with the data
Locked or corrupted .accdb filesSQLite on the server, with Back Up Database and Compact and Repair

And a few things Access never had

On Render
An event that runs as each record's copy of a control is drawn, so code can colour rows in a continuous form.
JavaScript modules
In place of Windows DLLs: write a function, export it, and call it from VBA. It runs in a sealed sandbox with no network.
Built-in libraries
UK bank holidays and working days, British National Grid and OS grid references, chainage along a line, and statistics, ready to tick in References.

Bring your database across

Moving an existing Access application is mostly familiar work, done once.

  1. Import the tables

    Pick your .accdb or .mdb and tick the tables. Field types come with them, and AutoNumber values are kept so related records still match.

  2. Rebuild queries, forms and reports

    In the same Query Design grid, form designer and report designer. Most of it is drag, drop and set properties, as you did the first time.

  3. Paste in your VBA

    Compile tells you what needs changing, such as file access or a Declare that a web page can't do.

  4. Add your users

    Give each person a sign-in as an admin or a user, then send them the link.

Questions

Can we use it for real work yet?

Not yet. Web Access Builder is in active development, so features are still changing and there may be bugs. Please test it with copies of your data, keep your Access database as the working version, and tell us what you find. We'll say here when it's ready for production use.

Is this Microsoft Access?

No. Web Access Builder is an independent product that works the way Access does. It runs in a browser, doesn't need Access installed, and isn't made by or connected with Microsoft.

Can I open my .accdb file in it?

You import the tables from it, with their field types and AutoNumber values. For now, queries, forms, reports and code are rebuilt in Web Access Builder's own designers, which work like Access's. Importing those from the .accdb is on the way.

Will my VBA run?

Much of it, as written: form and control events, Me, DoCmd, MsgBox, DLookup and DCount, DAO recordsets, error handling and class modules. Things a web page can't do, such as Shell, file access, Windows DLLs and automating Excel, are flagged when you compile. JavaScript modules stand in for DLLs.

Does it do reports?

Yes: grouping, totals, page numbers and Print Preview with page size, margins and orientation. Print them, or save them as PDF from the print dialog. Subreports and report events are next.

Where is our data kept?

In a SQLite database on the server that runs your instance. Admins can download a complete copy at any time with Back Up Database.

Who can change the design?

Only admins. They design tables, queries, forms and code, and manage who can sign in. Users open what's been built and work with the data, and can't open Design view.
